## TCP Connections and Reliable Delivery

TCP provides a reliable, ordered byte-stream service between two processes on top of IP, which may lose, duplicate, reorder or corrupt packets. Applications reach it through the sockets API: a server calls socket(), bind(), listen() and accept(), while a client calls connect().

A connection begins with the three-way handshake. The client sends a SYN segment carrying its initial sequence number; the server replies with a SYN-ACK that carries its own initial sequence number and acknowledges the client's; the client answers with an ACK, after which data can flow in both directions. Initial sequence numbers are chosen randomly, so segments from old connections and spoofed segments are unlikely to be accepted. A server under a SYN flood attack can protect itself with SYN cookies, which encode the connection state in the sequence number instead of storing it.

Every byte has a sequence number. The receiver sends cumulative acknowledgements: an ACK number of N means that all bytes before N have arrived and N is the next byte expected. The sender keeps unacknowledged data and retransmits it when the retransmission timeout, RTO, expires. The RTO is derived from a smoothed estimate of the round-trip time plus four times its variation, and it doubles after each timeout, which is exponential backoff. Waiting for a timeout is slow, so TCP also uses fast retransmit: three duplicate ACKs for the same sequence number strongly suggest that one segment was lost while later ones arrived, and the sender retransmits the missing segment at once. Selective acknowledgements, SACK, tell the sender exactly which blocks arrived, so several losses can be repaired in one round trip.

A connection is closed by each side sending a FIN that the other acknowledges, so a full close takes four segments. The side that closes first enters the TIME_WAIT state for twice the maximum segment lifetime, 2MSL, before releasing the connection. TIME_WAIT ensures that the final ACK can be retransmitted if it is lost, and that delayed segments from the old connection die out before the same address and port pair is reused. An RST segment aborts a connection immediately.

## Flow Control and the Sliding Window

Flow control prevents a fast sender from overwhelming a slow receiver. It is an end-to-end agreement between the two hosts about the receiver's buffer space, and it is entirely separate from congestion control, which protects the network in between.

TCP implements flow control with a sliding window. Every ACK carries a receive window, rwnd, the number of bytes of free space in the receiver's buffer beyond the acknowledged point. The sender may have at most rwnd bytes of unacknowledged data outstanding; as the application reads data and ACKs arrive, the window slides forward and more data may be sent. The amount actually in flight is limited by the smaller of rwnd and the congestion window, cwnd.

If the receiving application stops reading, the advertised window shrinks to zero and the sender must pause. To avoid a deadlock in which the window update that reopens the window is lost, the sender periodically transmits a zero-window probe, a tiny segment that forces the receiver to repeat its current window. Silly window syndrome, in which the window opens a few bytes at a time and the sender transmits tiny segments, is avoided by receivers that delay small window updates and by Nagle's algorithm on the sender, which holds back small segments while earlier data is unacknowledged.

The 16-bit window field limits the window to 64 KiB, too little for modern networks. A sender can keep at most one window of data in flight per round-trip time, so throughput is bounded by the window size divided by the RTT: with a 64 KiB window and a 100 ms RTT that is only about 5 Mbit/s. To fill a link, the window must be at least the bandwidth-delay product, the bandwidth multiplied by the RTT. The window scale option, negotiated during the handshake, multiplies the window field by a power of two up to 2^14, allowing windows of about 1 GiB.

The same sliding-window idea appears in link-layer protocols. Go-Back-N retransmits everything from the first lost frame onward, while selective repeat buffers out-of-order frames and retransmits only the missing ones.

## TCP Congestion Control

Congestion control stops senders from overloading the network itself. When routers receive more traffic than their outgoing links can carry, their queues grow and eventually drop packets, and if every sender simply retransmitted at full speed the network would collapse, with links busy carrying packets that are dropped further along the path. TCP treats packet loss as the signal of congestion, and each sender limits itself with a congestion window, cwnd, the number of bytes it may have in flight according to its estimate of the path capacity.

A new connection starts in slow start. Despite the name, cwnd grows quickly: it begins at a small initial window, today usually 10 segments, and increases by one maximum segment size, MSS, for every ACK received, so it doubles every round-trip time. Slow start continues until cwnd reaches the slow start threshold, ssthresh, or a loss occurs.

Above ssthresh the sender is in congestion avoidance and follows additive increase, multiplicative decrease, AIMD: cwnd grows by about one MSS per round-trip time and is cut multiplicatively when a loss is detected. When several flows share a bottleneck link, AIMD drives them toward equal shares of the bandwidth, which is why it is the basis of TCP fairness.

The classic variants differ in how they react to loss. TCP Tahoe treats every loss the same way: it sets ssthresh to half of cwnd, resets cwnd to one segment and begins slow start again. TCP Reno distinguishes the two loss signals. A retransmission timeout still sends cwnd back to one segment, but three duplicate ACKs trigger fast retransmit followed by fast recovery: ssthresh is set to half the current cwnd, cwnd is set to that new ssthresh rather than to one segment, and the sender continues in congestion avoidance, since duplicate ACKs show that data is still flowing. NewReno improves recovery when several segments are lost from one window.

On fast long-distance paths, growing by one MSS per RTT takes far too long to reach full speed. CUBIC, the default in Linux, grows cwnd as a cubic function of the time since the last loss, probing quickly away from the previous maximum. BBR, developed by Google, does not use loss as its main signal; it estimates the bottleneck bandwidth and the minimum RTT and paces packets to match them.

## IP Addressing and Routing

The Internet Protocol, IP, delivers datagrams between hosts on a best-effort basis: packets may be lost, duplicated or reordered, and reliability is left to higher layers. An IPv4 address is 32 bits, written in dotted decimal such as 192.168.1.20; IPv6 uses 128-bit addresses written as groups of hexadecimal digits, largely because the IPv4 address space has run out.

Addresses are allocated in blocks using classless inter-domain routing, CIDR. A prefix such as 10.4.0.0/16 means that the first 16 bits identify the network and the remaining 16 bits identify hosts within it, so the block holds 65,536 addresses. A subnet mask such as 255.255.255.0 is an equivalent way of writing a /24 prefix. Network address translation, NAT, lets many devices with private addresses share one public address by rewriting addresses and ports at the edge router.

Routers perform two distinct jobs. Forwarding is the per-packet, data-plane action of moving a datagram from an input port to the right output port. It uses a forwarding table and the longest prefix match rule: when several table entries contain the destination address, the router chooses the most specific, longest one, so a /24 entry overrides a /16 entry that also covers the address. Routing is the control-plane process that computes those tables.

Within one organisation's network, an autonomous system, two families of routing algorithms are used. Link-state protocols such as OSPF flood each router's view of its links to every other router, so all routers learn the full topology and run Dijkstra's shortest-path algorithm. Distance-vector protocols such as RIP use the distributed Bellman-Ford algorithm: each router periodically tells its neighbours its current distance to every destination. Distance-vector routing is simple but converges slowly after a failure and can suffer from the count-to-infinity problem, in which routers keep increasing their distance to an unreachable destination through each other; split horizon and poisoned reverse mitigate it. Between autonomous systems the Internet uses BGP, a path-vector protocol in which every route carries the list of autonomous systems it traverses, which prevents loops and lets operators apply routing policy instead of pure shortest paths.

Every IP header carries a time-to-live, TTL, which each router decrements; a packet whose TTL reaches zero is discarded, so packets cannot circulate forever in a routing loop.

## The Domain Name System

The Domain Name System, DNS, translates human-readable host names such as www.example.com into IP addresses. It is a distributed, hierarchical database: no single server knows every name, and authority is delegated down a tree of zones.

At the top are the root servers, reachable through 13 well-known names that are served by many anycast instances. Below them, top-level domain, TLD, servers are responsible for zones such as .com, .org and country codes such as .ca. Authoritative name servers hold the actual records for an organisation's own zone, such as example.com.

A client's stub resolver sends its query to a recursive resolver, typically run by the ISP or by a public service. The recursive resolver does the work: it asks a root server, which refers it to the TLD servers; it asks a TLD server, which refers it to the authoritative servers for the domain; and it asks an authoritative server, which returns the answer. Those referrals are iterative queries, in which each server replies with the best information it has instead of fetching the answer itself. DNS queries normally travel over UDP port 53 and fall back to TCP for large responses and zone transfers.

Common resource record types include A, which maps a name to an IPv4 address; AAAA, which maps a name to an IPv6 address; CNAME, which declares a name to be an alias of another, canonical name; MX, which names the mail servers for a domain with preference values; NS, which names the authoritative servers for a zone; and TXT, which holds arbitrary text used for purposes such as domain verification and email authentication.

Caching makes DNS fast and keeps load off the root and TLD servers. Every record carries a time-to-live, TTL, in seconds, and resolvers may answer from their cache until the TTL expires. The price is staleness: after an operator changes a record, resolvers around the world may keep serving the old address until their cached copies expire, so DNS is only eventually consistent. Operators lower the TTL ahead of a planned migration so that the change propagates quickly. Because plain DNS responses are unauthenticated, attackers can attempt cache poisoning; DNSSEC adds signatures that let resolvers verify the answers.

## The Link Layer: Ethernet, Switches and ARP

The link layer moves frames between nodes that share a physical link or a local network. Ethernet is the dominant wired technology. Each network interface has a 48-bit MAC address, written as six hexadecimal bytes such as 3c:22:fb:10:0a:7e, which is assigned by the manufacturer and is meaningful only within the local network, whereas IP addresses are routable across networks. An Ethernet frame carries destination and source MAC addresses, a type field naming the payload protocol, a payload of up to 1500 bytes, which defines the usual MTU, and a CRC for error detection.

Classic shared Ethernet used CSMA/CD, carrier sense multiple access with collision detection. A station listens before transmitting, aborts when it detects a collision, sends a jam signal and then waits a random time chosen by binary exponential backoff: after the n-th collision it waits K slot times, with K chosen at random between 0 and 2^n - 1, capped at 1023. Modern switched, full-duplex Ethernet has no collisions at all, so CSMA/CD survives mainly as history. Wi-Fi cannot detect collisions while it transmits and uses CSMA/CA, collision avoidance, with acknowledgements instead.

An Ethernet switch forwards frames only toward their destination, and it is self-learning: when a frame arrives, the switch records the source MAC address and the port it came in on in its switch table. To forward a frame it looks up the destination address, and if the address is unknown it floods the frame out of every other port. Entries age out after a few minutes. Switches connected in a loop would circulate broadcast frames forever, so the spanning tree protocol disables redundant links.

The Address Resolution Protocol, ARP, finds the MAC address that corresponds to an IP address on the same subnet. A host that wants to send to 192.168.1.7 broadcasts an ARP request asking who has that address; the owner answers with its MAC address in a unicast ARP reply, and the sender stores the mapping in its ARP cache for a limited time. To reach a host on another network, the sender instead uses ARP to find the MAC address of its default gateway router. Because ARP replies are not authenticated, an attacker on the LAN can use ARP spoofing to intercept traffic.

## Router Queues and Packet Scheduling

Every router output port has a buffer in which packets wait when they arrive faster than the link can transmit them. Queueing delay is the variable part of end-to-end latency, and when the buffer is full, arriving packets must be dropped.

The simplest policy is drop-tail with first-in, first-out service: packets are sent in arrival order and new arrivals are discarded when the queue is full. Drop-tail has two problems. Many TCP flows tend to lose packets at the same moment and back off together, a pattern called global synchronisation. And oversized buffers cause bufferbloat: loss-based congestion control keeps them full, adding hundreds of milliseconds of delay for every flow that shares the link, which ruins interactive applications such as games and video calls.

Active queue management, AQM, drops or marks packets before the buffer is full in order to signal congestion early. Random early detection, RED, drops arriving packets with a probability that rises with the average queue length between a minimum and a maximum threshold. CoDel, controlled delay, instead measures how long each packet spent in the queue; if the minimum sojourn time stays above a 5 ms target for a 100 ms interval, it starts dropping, so the queue drains to a low standing delay. Explicit congestion notification, ECN, lets an AQM router mark packets instead of dropping them, and the receiver echoes the mark so that the sender slows down without suffering a loss.

Packet scheduling decides which queued packet is transmitted next when there are several queues. Strict priority queueing always serves the highest-priority non-empty queue, which suits voice traffic but can starve the lower classes. Round-robin scheduling cycles through per-flow queues, sending one packet from each in turn; because packets differ in size, flows with large packets get more bandwidth, so deficit round robin gives each queue a quantum of bytes per round instead. Fair queueing approximates bit-by-bit round robin, giving every active flow an equal share of the link no matter how aggressively it sends, and weighted fair queueing, WFQ, assigns shares in proportion to weights. FQ-CoDel, the default queueing discipline on many Linux distributions, combines per-flow fair queueing with CoDel on each queue.

## HTTP and QUIC

HTTP is the request-response application protocol of the web. A client sends a request with a method such as GET or POST, a path and headers, and the server returns a status code, headers and a body. Status codes are grouped by their first digit: 2xx for success, such as 200 OK; 3xx for redirection, such as 301 Moved Permanently; 4xx for client errors, such as 404 Not Found; and 5xx for server errors, such as 503 Service Unavailable. HTTP itself is stateless, and cookies let servers associate requests with a session.

HTTP/1.0 opened a new TCP connection for every object, paying for a handshake and a slow-start period each time. HTTP/1.1 made persistent connections the default, so many requests reuse one connection, and added pipelining, which allowed several requests to be sent without waiting but required the responses to come back in order. One slow response therefore blocks every response behind it, a problem called head-of-line blocking, so pipelining was rarely enabled in practice and browsers opened about six parallel connections per host instead.

HTTP/2 keeps the same semantics but uses a binary framing layer that multiplexes many concurrent streams over a single TCP connection, with header compression, HPACK, and stream prioritisation. This removes head-of-line blocking at the HTTP layer but not at the transport layer: because TCP delivers one ordered byte stream, a single lost packet stalls every stream until it is retransmitted.

HTTP/3 runs over QUIC, a transport protocol built on UDP. QUIC implements reliable delivery and congestion control in user space with independent streams, so a loss on one stream does not delay the others. It integrates TLS 1.3 into its handshake, so a new connection is usually ready after a single round trip, and a resumed connection can send data immediately with 0-RTT, at the cost of possible replay of that early data. QUIC connections are identified by connection IDs rather than by the address and port four-tuple, so they survive a phone switching from Wi-Fi to a cellular network. Because QUIC encrypts almost all of its headers, middleboxes cannot inspect or tamper with transport state, which also lets the protocol evolve without being blocked by old network equipment.
